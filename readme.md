# CleanChatGPT

用于清理 macOS 上 ChatGPT / Codex 本地数据的第三方工具。默认只读预览，只有显式传入 `--apply` 才会直接删除计划中的本地状态。**执行时不备份、不移入废纸篓，也没有自动回滚。** 文稿中的用户内容、检测到的 Git 仓库和明确的工作文件原地保留。

工具不会自动清理云端内容、钥匙串或个人浏览器。保留工作文件、共享配置和未知条目意味着可能仍有使用记录，因此不承诺抹除全部安装和使用痕迹。

**验证状态：仅完成源码与语法的静态检查。尚未执行清理脚本，包括 `--help`、`--dry-run`，未进行运行时验证或删除测试。以下命令均为未执行的使用示例。**

## 使用前提

- macOS，当前普通用户，Python **3.11 或更高版本**；不要使用 `sudo`，不要 `source` 入口脚本。
- 入口为 `clean-chatgpt-codex.sh`，实现为同目录的 `cleanup_chatgpt_codex.py`，两者需一起保留。
- 实际操作应由你在退出 ChatGPT、Codex、相关 CLI、辅助服务及会写入目标目录的编辑器／后台任务后，从独立终端审阅并调用。脚本会检查相关进程，但不会替你结束它们；检测到运行进程或无法可靠检查时会停止执行。
- 删除前必须确认计划中的每一项可以丢弃。不能因为路径名包含 ChatGPT 或 Codex，就认为里面没有工作内容；额外要保留的路径用 `--protect` 指定。

## 先审阅预览，再决定执行

**以下示例未执行；请勿把它们当作已经完成的操作。** 在本仓库目录中，无参数与 `--dry-run` 都只显示计划，不修改文件、不打开网页：

```sh
./clean-chatgpt-codex.sh
./clean-chatgpt-codex.sh --dry-run
```

检查输出列出的待删除对象、“保留项”“边界与待核对项”。确认 Documents、技能、生成文件及自己的项目位于保留范围；根据需要添加 `--protect`，然后用完全相同的范围重新预览。

**以下是会直接删除文件的未执行示例。** 只有你确认计划并退出相关应用后，才自行调用：

```sh
./clean-chatgpt-codex.sh --apply
```

此时还需输入 `DELETE` 确认。`--apply --yes` 仅跳过这次交互确认，不跳过进程检查、路径保护或变更检查；单独使用 `--yes` 会报错。

## 清理范围与保留规则

默认候选范围包括 Codex 数据目录中明确识别的本地状态，以及 ChatGPT/Codex 的应用支持目录、缓存、日志、偏好、应用 Cookie、容器、窗口状态、诊断报告和当前用户的指定应用临时目录。环境变量 `CODEX_HOME`、`CODEX_SQLITE_HOME` 和 Codex 配置中的 `sqlite_home`、`log_dir` 也会参与发现。

`~/Documents/ChatGPT` 与 `~/Documents/Codex` **中的用户文件和子目录原地保留**，包括非 Git 项目、生成文件和未知目录。这里只清理根层级的 `.DS_Store`、`.localized` Finder 元数据；根目录随后确实为空时才可移除，不递归删除其中的用户内容。

`~/.codex` 及其他指定的 Codex 数据根目录只将明确的状态和应用设置条目纳入计划；有保留项时会拆分清理，并保留其祖先目录。工作树、`skills`、`generated_images`、`attachments`、`visualizations`、`pets`、独立的 `AGENTS.md`、`rules`、`prompts`、`automations`、`envs`，以及未识别的根层级文件／目录保留原位。已识别的下载插件包和安装应用内的同名资源属于安装文件，仍可清理。

`config.toml` 和 `*.config.toml` 属于会清理的应用设置，**其中内嵌的 `custom_instructions` 也会随文件删除**。这与保留独立的指令文件不同；需要保留配置时，用 `--protect` 指定相应文件。新版本出现的未知状态可能留下，需人工核对。

工作文件保护依赖已知位置、名称和 Git 标记，无法判断任意文件的实际用途。如果你把工作文件手工放在已识别的缓存或状态目录内，请显式使用 `--protect`，不要假定工具能自动辨认它。

以下内容原地保留，并在计划中说明；其必要的祖先目录也会保留：

- 检测到 `.git` 的 Git 工作目录、识别出的裸仓库，以及 Codex 根目录下已知的工作树相关目录，保护未提交、未推送成果。
- `--protect` 指定的文件或目录、共享的 `~/.agents`、清理工具自身，以及位于候选范围内的当前工作目录。
- 挂载点、不同文件系统内的目录、socket/FIFO 等特殊对象。

候选根目录或其路径组件为符号链接时，脚本会拒绝处理或保留并提示，不沿该链接扩大清理范围。已纳入普通目录内部的符号链接只处理链接本身，不递归跟随其目标。某个链接目标若同时是独立明确列出的候选目录，仍按该目录自身的计划处理。

权限错误、配置解析错误、无法可靠检查进程、计划之后文件／目录发生变化等情况会使操作停止。脚本逐项检查并直接删除；如果已经处理了一部分目标，后续停止不会撤销之前的删除。保留终端输出，核对已删除、未处理和保留的条目，不要把部分完成视为全部清理成功。

## 参数

| 参数 | 行为 |
| --- | --- |
| `--dry-run` | 只读预览，与默认行为相同；不能与 `--apply` 同用。 |
| `--apply` | 直接删除计划中的对象，不备份。 |
| `--yes` | 仅配合 `--apply` 跳过交互确认，不跳过保护或检查。 |
| `--remove-apps` | 将 `/Applications`、`~/Applications` 下名为 `ChatGPT.app`、`ChatGPT Classic.app`、`Codex.app`、`OpenAI Codex.app` 且 bundle ID 已核实的应用包纳入删除计划。默认保留应用；删除应用也会删除其内置 CLI，不自动卸载独立包管理器安装。 |
| `--protect PATH` | 原地保留指定文件或目录，可重复。 |
| `--codex-home PATH` | 额外的 Codex 数据根目录，可重复，不替换默认根目录；自定义根需有可识别标记，同样仅清理明确状态条目。 |
| `--sqlite-dir PATH` | 额外数据库目录，可重复；只处理明确文件名名单，不删除共享目录整体。 |
| `--log-dir PATH` | 额外日志目录，可重复；只处理识别出的 Codex 日志。 |
| `--no-open` | 兼容旧参数；新版始终不会自动打开网页。 |

路径参数及配置里的路径应使用无 `..` 的绝对路径；支持 `~`、`~/`，不支持相对路径。脚本只把配置当数据解析，不执行配置，也不展开其中的 `$HOME`、`${变量}` 或命令。下例里的 `"$HOME/..."` 由终端 shell 先展开成绝对路径。

下面是**未执行的预览示例**，路径仅作示意，请先替换为自己确认的位置：

```sh
./clean-chatgpt-codex.sh --dry-run \
  --codex-home "$HOME/CodexData" \
  --sqlite-dir "$HOME/CodexDatabases" \
  --log-dir "$HOME/CodexLogs" \
  --protect "$HOME/.codex/config.toml" \
  --protect "$HOME/Library/Application Support/Codex/keep-this-folder"
```

自定义 SQLite 目录只匹配 `state`、`logs`、`goals`、`memories`、`queue`、`thread_history` 这些家族的 `.sqlite` 文件（可带 `_数字` 版本号）、`codex-dev.db`，及其 `-wal`、`-shm`、`-journal` 附属文件。自定义日志目录只匹配 `codex-tui.log`、`codex-login.log` 及数字轮转后缀。其他条目保留并提示，不按扩展名批量纳入；新版本产生的其他文件仍可能需要人工核对。

Codex 数据根中的会话目录只识别日期目录与 `rollout-*.jsonl`；日志、数据库和 shell 快照也按已知文件名格式筛选，未知内容保留。删除期间不会将新出现的文件加入原计划，发现目录变化会停止。

## 需要另外核对的内容

云端聊天与文件、Memory、Projects、共享链接、连接应用、云端浏览器、钥匙串、个人浏览器、其他设备、独立安装来源及系统备份不由本脚本自动清空。项目外部工作目录及未识别的位置也不通过全盘搜索或模糊关键词纳入。

请阅读 [CLEANUP-NOTES.md](CLEANUP-NOTES.md)：其中列有官方资料链接、核对日期、已核实的文档范围与未核实的当前界面入口。官方文档核对不代表已访问当前账号，也不代表这些人工清理已经完成。
